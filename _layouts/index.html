What it does

One crate for the random numbers a program needs

Each card opens its section on the features page.

Xoshiro256++ by default

Random::new() seeds a 32-byte Xoshiro256++ generator from the operating system. Bounded integers are unbiased and floats use every mantissa bit.

How the default works

Five backends, one API

Mersenne Twister, PCG32, PCG64 and a ChaCha20 generator for secrets sit behind the same Random type.

Choose a backend

Reproducible sequences

The same seed gives the same sequence. Snapshot a generator with serde, or split off a stream 2128 draws ahead.

Distributions

Uniform, normal (Ziggurat), exponential and Poisson built in, and a Distribution trait for your own.

Quasi-random sequences

Halton, Sobol and Van der Corput low-discrepancy sequences for Monte Carlo integration.

no_std and WebAssembly

Where it runs

Backends

Fast by default, secure when you ask

The default and the alternatives are the same Random type. Only ChaCha20 is suitable for secrets.

Default

Xoshiro256++

32 bytes of state. The default for simulations, games, sampling and tests. Not for secrets.

Compare the backends

pcg feature

PCG32 and PCG64

16 and 32 bytes of state. PCG32 is the fastest backend in the published benchmarks.

See the timings

crypto feature

ChaCha20

A cryptographically secure generator from rand_chacha, for tokens, keys and anything an attacker would want to predict.

When you need it

Install

Random numbers in a few lines of Rust

Add the crate, create a generator and draw. vrd 0.0.12 needs Rust 1.85 or newer.

  • cargo add vrd
  • cargo install vrd
Read the getting started guide
Security

Predictable by design, unless you ask otherwise

The default generator is fast and statistically good, and anyone who sees enough of its output can predict the rest.

For session tokens, API keys, password-reset links and nonces, turn on the crypto feature and use Random::new_secure(). The security page sets out what vrd does and does not promise.
